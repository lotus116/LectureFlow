# LectureFlow 界面视觉改进任务书

日期：2026-10-31。状态：设计与 Cursor 实施任务，尚未实现或视觉验收。

## 1. 范围与目标

产品行为仍以 `PRODUCT_DESIGN-2026-10-31.md` 为准。此次只改善 SwiftUI 界面呈现、信息层级、可读性及交互反馈，不更改录音、任务、术语和数据保护规则，不增加笔记、API、知识库或新产品功能。

目标：安静、清晰、值得长时间使用的 macOS 学习工具。以原生桌面应用的工作空间为参考：侧栏定位、工具栏操作、正文阅读；不把网页落地页、手机布局或后台仪表盘搬进应用。

保留现有琪露诺 Logo 和冰蓝视觉身份。角色只在应用图标、轻量品牌入口或少量空状态中出现；录音和转写正文区不增加人物插画、水印或花纹。README 的品牌横幅与日常工作界面承担不同职责。

## 2. 当前可见的结构问题

本轮检查了 0.6.0 的 `CourseHomeView`、`LectureFlowApp`、`SessionControls`、`Chrome` 等源码；旧截图仅作历史参考。实施者必须先构建并观察当前界面，不能把源码推断当作实际截图验收。

- 多层 HStack/VStack、分段选择和卡片容易堆叠，消耗垂直空间。
- 录音计时、状态、记录方式、说明、模型入口和结束后动作集中在一个区域，主次不够鲜明。
- 样式已有少量 token，但字号、强调色、按钮与层级仍分散在各页面。
- 空状态偏向解释内部行为；常用操作区文字过多。
- 深色模式容易出现相邻灰色表面难以区分、正文对比偏弱的问题。

这些是需要实机验证的设计诊断，不是已确认的运行错误。

## 3. 统一视觉规范

### 配色与表面

- 以系统语义背景、正文、次级文字、分隔线为基础；冰蓝作为少量强调色，服从系统辅助功能和用户强调色。
- 内容背景尽量平整。侧栏、内容、浮层靠轻微表面差异和留白区分，不给每一行加独立圆角卡片。
- 红色只表达录制或破坏性操作，橙色表达需要注意的状态；普通按钮不同时使用多种饱和色争抢注意力。
- 明暗主题分别检查，不用简单反色。普通正文对比度目标至少 4.5:1，重要控件边界与状态不只靠颜色识别。
- 不增加全屏渐变、发光描边、霓虹、厚阴影或铺满正文的玻璃效果；系统材质可用于侧栏/浮层，但不能牺牲字幕可读性。

### 排版与尺寸

- 使用系统字体和 SF Symbols；不引入在线字体或全局字体依赖。中文、英文和数字均检查。
- 主标题建议 22–26 pt；分区标题 13–15 pt；常规正文 13–15 pt；说明 11–12 pt。转写内容建议从 16–18 pt 起调整，字幕字号独立设置。
- 不将所有标题都设为 rounded/bold。只保留明确的标题、正文、辅助信息三级层次。
- 时间用等宽数字，计时不能挤压主操作；长课程名和长录音名有稳定的换行/截断策略和完整名称查看方式。
- 统一间距档位 4/8/12/16/24/32 pt，内容区常用边距 24 pt；圆角以 6/10/14 pt 少量档位为起点，优先匹配原生控件。
- 侧栏起始约 240–260 pt；在现有最小窗口约 920×610、常用 1180×790 和 1440×900 下检查。尺寸是布局起点，不要求锁死像素或扩大最小窗口逃避问题。

### 控件与反馈

- 每个任务区域保留一个明确主操作，次要操作用普通按钮或菜单；不删除已确认操作。
- 侧栏、搜索、列表、分段控件优先用原生组件，统一 controlSize、图标尺寸、基线和内边距。
- 图标按钮有 tooltip 与 accessibilityLabel，支持键盘焦点；hover 不是唯一发现操作的方式。
- 录音中、暂停、不保存音频、等待模型等关键状态可见；后台技术细节与重复教学说明放次级位置，不能把重要失败提示藏起来。
- 动效只用于状态/选择过渡，建议约 120–200 ms；尊重减少动态效果、降低透明度、提高对比度。禁止持续脉冲装饰、假波形和假进度。

## 4. 各页面要求

| 页面 | 视觉主次与要求 |
|---|---|
| 侧栏 | 课程与 Lecture 层级清楚，选中态单一；底部设置/废纸篓轻量；保留拖放反馈，避免重复品牌大标题占位 |
| 课程主页 | 课程名和数量简洁；“开始新 Lecture”为主，创建/导入次之；课程资料入口明显但不抢主动作。Lecture 列表是主内容，日期、录音数与状态按已有真实数据展示，无新数据不编造 |
| Lecture 顶部 | 名称、必要元信息、紧凑采集控制；一眼看到是否保存音频、计时、开始/暂停/继续及结束；录音/转写切换下方尽快进入内容，不堆满介绍卡片 |
| 录音页 | 使用对齐的列表行呈现播放、名称、时长和更多操作；拖动顺序清楚。正常列表不用每行重阴影；空状态只给短说明和当前需要的操作 |
| 转写页 | 正文成为视觉中心，英文在上中文在下；时间戳轻量，段落间距稳定。工具区容纳结果切换、搜索、语言与导出。编辑、播放、重新翻译和历史入口保留；不靠逐段厚卡片分隔 |
| 课程资料 | 文件列表和处理状态为主；批量导入明显；术语数与查看辅助术语为次级。不要重新出现资料范围三选项、采用审核流程或术语大表抢占首页 |
| 悬浮字幕 | 中文主、英文次，阅读区优先；控制栏精简，hover/键盘可发现；保留采集状态、不保存音频和返回主窗口；对浅色网页、深色视频背景分别检查 |
| 设置/任务/废纸篓 | 原生表单或列表，四类设置清楚；等待/暂停/失败原因可读，删除和清空明确区分；不改变确认规则 |

## 6. 实施与验收

1. 先运行当前应用，用隔离资料库和自造的非隐私内容观察关键页面，记录具体问题和改前截图。
2. 先用一个课程主页和一个有内容的转写页建立一致方向，再应用到其他页面；不要求用户在一批模糊风格中重新选择。
3. 在 `Chrome.swift` 或合适的少量文件中统一语义 token、控件样式、列表行和空状态；避免一份超大 View 继续膨胀，也不为美化引入架构重写。
4. 实现真实 SwiftUI 界面，不交付 HTML 原型代替原生修改；不改音频线程、模型策略、数据库含义或任务状态来迁就布局。
5. 实际检查明/暗主题，以及上述三个窗口尺寸。关键页面均覆盖；空状态、长文本、加载、失败、录制/暂停和资料处理中不能挤压或跳动。截图只使用合成数据，不能提交真实课件、转写或本机路径。
6. 键盘可操作；辅助标签、对比度、焦点及降低透明度/减少动态效果核对；运行相关 Python 检查和原生测试、构建，检查暂停/继续、隐藏悬浮与退出确认没有回归。
7. 交付同场景、同尺寸的改前/改后截图与简短设计说明；未能运行的页面明确待验收。构建通过不等于视觉验收通过，不编造用户使用效果或性能指标。
8. 更新 STATUS/SD_TRACKING 时区分“代码已改”“截图已检查”“真机交互待测”。只提交本任务变更，日常推送不发版。
