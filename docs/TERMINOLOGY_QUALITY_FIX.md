# 课程术语质量修复 · 2026-10-31

对应 SD-03、LF-06、LF-04。状态：实现与行为回归已完成；真实模型效果、延迟及长时评估仍待反馈，不记为通过。

## 问题与结论

用户反馈自动词表中出现普通词错误消歧、缩写原样回填，以及把整句解释当译名的情况。这暴露了实现与设计的共同缺口：

1. 旧提取器把很多长度超过七个字符的单词都当候选，甚至从 `X is ...` 句子生成定义；候选量不等于术语质量。
2. 中文补全复用句子翻译方法、把定义放入上下文，仅检查非空和 300 字长度，允许解释或背景句进入词表。
3. 自动条目和人工/课件对照共用 confirmed 状态；新实现自动启用后，模型猜测的中文也被直接传入翻译。
4. ASR 容错选择曾把很短的前缀匹配直接记成高相关，相关页也能抬高弱匹配。
5. 单段重新翻译传整个快照词表，绕过了实时/离线路径已有的当前语句匹配。

英语原样保留不必然是错误：代码、产品名和不明缩写可以保留原文。不能用“中文栏已填满”表示成功，更不能将自动生成视作语义已核实。

## 修正后的产品规则

- 自动维护仍无逐词审核门槛。英文拼写证据与中文译名可信度分别处理，不引入复杂知识库或 API。
- 英文侧优先保留缩写、代码标识符、专业短语及简短标题证据，去掉“长单词即术语”的规则，过滤链接和版权信息；只有少量与当前声音草稿充分相关的词才作 ASR 提示。
- 中文侧只将短且有效的课件明确中英对照、人工校正传给翻译。自动模型译名仅显示为建议，不自动约束翻译。
- 资料间译名冲突时不采用任意一份，显示冲突；人工校正可解决。删除冲突资料后重新计算剩余证据。
- 本地模型使用独立术语任务和有界源文本片段，限制输出长度。代码标识符和无明确全称的缩写默认保留英文，不逐项浪费翻译调用。原文回填、解释句、截断及格式异常留空并继续批次，不让一项坏输出拖垮全部任务；无法提供译名不会自动无限重试，可主动补全重试。
- 不要求用户审核全部术语；不确定时退回正常语句翻译，用户只在需要纠错时编辑。

## 数据、恢复和旧结果

- 新索引版本为 2。下次打开课程资料或创建字幕/转写上下文时，以已缓存页文字在事务内重新整理派生条目，无需重新导入原文件。
- 旧自动中文被清除，旧低质量候选退休；人工调整、停用记录、源文件、转写与历史快照不变。自动更新不会覆盖人工编辑，包含用户特意留空的译名。
- 新任务记录 `source_or_manual_v2` 词表策略。缺少该标记的旧快照在执行/单段重译时不再沿用无来源区分的旧中文词表；不改写快照本身及已完成结果。
- 实时与离线、单段重新翻译都按当前语句匹配；只刷新词表不会重跑整堂。若历史结果已受旧译名影响，用户可主动生成新版本。
- 本次不手工清空用户资料库，不重启或中止当前采集；新版后台按上述规则刷新派生索引。构建预览在 `dist/term-quality-preview/LectureFlow.app`，先结束采集并退出旧应用，再启动预览或运行 `zsh scripts/run`。

## 实现入口

- `terminology.py`：术语形态、短译名格式门和旧快照策略边界；格式合格不代表语义正确。
- `knowledge.py`：提取、带版本的索引重建、人工优先、冲突处理、补全任务的逐项容错与检查点。
- `documents.py`：归并来源、删除后重建、按来源过滤中文、保留独立英文提示。
- `inference_policy.py`：短译名匹配、提高软匹配要求、修复短前缀高分。
- `adapters.py`：独立 `translate_term`；`worker.py` / `live.py` / `cli.py` / `library.py`：一致的使用边界。
- `MaterialsView.swift`：区分“仅拼写辅助”“译名建议”“课件对照”“人工校正”“译名冲突”，不再统一标为已启用。
