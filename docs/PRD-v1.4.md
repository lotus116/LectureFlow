# LectureFlow — 产品需求文档（PRD）

**版本：** V1.4  
**产品类型：** macOS 本地 AI 课堂助手  
**目标设备：** MacBook Air M5 · 16GB RAM  
**开发方式：** 自主开发应用，复用成熟开源 AI 模型及底层框架  
**产品理念：** 极简、准确、低延迟、稳定、本地优先

---

## 1. 产品定位

LectureFlow 是一款面向大学英语授课场景的本地 AI 课堂助手，集**课程管理、录音、语音识别、实时翻译、课件知识增强与 AI 学习总结**于一体。

主要解决以下问题：

- 教师口音明显、语速过快，普通 ASR 难以准确识别。
- 专业术语、缩写等容易被错误识别和翻译。
- 实时翻译缺乏上下文，容易出现误译或表达不完整。
- 长时间课堂中存在休息、闲聊等不需要录音或翻译的内容。
- 历史录音、课件、转写和总结难以统一管理。

**核心设计原则：**

1. **课程中心化：** 一门课程是文件夹，一节课堂是独立工作空间，包含任意数量的录音、课件、转写和总结。
2. **自由控制：** 录音、英文转写、中文翻译可以独立开启或停止，不要求连续运行。
3. **语义可靠：** 尽量快速提供初译，但不以牺牲准确性换取极限低延迟。
4. **上下文增强：** 充分利用用户上传的课件改善专业术语识别和翻译。
5. **本地优先：** 实时 ASR 和翻译在本机执行，云端仅用于可选的课后 AI 总结。
6. **极简体验：** 默认操作简单，高级功能和技术参数尽量隐藏。

## 2. 使用场景与平台

- **平台：** macOS，优先 Apple Silicon。
- **设备：** MacBook Air M5 16GB，兼顾性能、续航和内存。
- **输入：** 笔记本麦克风、外部麦克风或本地音频文件。
- **语言：** 英语授课为主，偶尔夹杂中文；翻译方向默认英译简体中文。
- **环境：** 实体教室，可能存在口音、语速快、回声及背景噪声。
- **时长：** 支持单节课堂持续三小时或更长，可多次暂停和恢复。

## 3. 产品结构与文件管理

### 3.1 课程层级

采用类似 macOS Finder 的文件夹管理逻辑：

```text
LectureFlow/
├── Deep Learning/
│   ├── Lecture 01/
│   │   ├── Audio/
│   │   ├── Documents/
│   │   ├── Transcripts/
│   │   └── Summaries/
│   └── Lecture 02/
├── Natural Language Processing/
└── Reverse Engineering/
```

每个 Lecture 可以包含：

- 软件实时录制的多段音频。
- 用户导入的多段历史录音。
- PPT、PDF 等课件。
- 英文转写与中文翻译。
- 课堂 AI 总结及导出文件。

### 3.2 文件管理功能

- 创建、重命名、移动、删除课程与课堂。
- 支持拖放文件、跨课堂移动或复制录音。
- 同一课堂内自由调整录音片段顺序。
- 支持通过 Finder 访问、备份和迁移数据。
- 自动维护音频、字幕、课件和总结之间的关联。
- 删除操作提供确认，避免误删原始录音。

底层使用真实文件夹保存用户资料，SQLite 负责索引、任务状态与数据关联。

**课堂是持久化容器，不等于一次连续录音任务。**

## 4. 课堂实时模式（Live Mode）

### 4.1 独立功能控制

用户可以在同一课堂内随时操作：

| 功能 | 开启 | 关闭 |
|---|---|---|
| 录音 | 采集并保存音频 | 停止保存，封存当前录音段 |
| 英文转写 | 识别并保存英文字幕 | 停止独立转写输出 |
| 中文翻译 | 生成实时中文字幕 | 停止翻译输出 |

技术依赖：

- 中文翻译需要底层 ASR，即使关闭英文字幕，必要的识别仍会在内部执行。
- 关闭录音后，仍可进行实时转写和翻译，但不会保存原始音频。
- 仅开启录音时，不需要运行 ASR 和翻译模型。
- 暂停、停止与舍弃应明确区分；舍弃当前录音需用户确认。

提供一键全部开启/暂停操作，并允许展开独立开关。

### 4.2 录音与课堂会话

- 一个课堂支持多次录音开始、暂停和恢复。
- 每次重新开始录音可以生成新的逻辑录音片段。
- 课间休息不会自动创建新课堂。
- 内部可按约五分钟分块保存长录音，提高可靠性。
- 用户看到的仍然是完整的录音片段，不需要管理内部存储块。
- 保留原始录制时间及用户自定义排列顺序。
- 关闭实时处理后，课堂可随时重新打开并继续添加内容。

### 4.3 实时语音识别

核心要求：

- 支持连续流式 ASR 和增量字幕输出。
- 重点优化教师口音、语速和专业术语。
- 支持临时识别结果和稳定识别结果。
- 支持基于课件的术语提示。
- 不因课件内容而无依据地修改老师讲话。
- 支持轻量与高精度模型切换。

初步模型候选：

- 默认：Qwen3-ASR-0.6B。
- 可选：Qwen3-ASR-1.7B。
- 推理框架优先考虑 MLX。

通过统一 ASR Adapter 封装模型，避免业务逻辑与特定模型绑定。

模型切换可以在句子边界进行，允许短暂加载等待，但不能丢失正在录制的音频。

### 4.4 实时翻译与上下文修订

采用双阶段翻译架构。

**阶段 A：快速初译**

- 目标是在有足够语义信息后，尽量于 1–2 秒内给出有用的初步中文。
- 允许句子不完整和后续修订。
- 不能为了抢速度而无依据地推测内容。
- 音频或语义不清晰时，可以延迟翻译或显示不确定状态。

**阶段 B：语义校准**

- 利用后续讲话、最近上下文及专业术语重新组织译文。
- 默认允许修订最近 1–3 句。
- 较旧、已稳定的字幕尽量保持不变。
- 区分临时、稳定、已修订和锁定状态。
- 保留必要的原始版本，避免校正过程覆盖真实识别信息。

翻译模型优先测试 Hy-MT2-1.8B，具体运行时及量化方案由 Mac 实测决定。

### 4.5 实时界面

**A. 字幕模式（Subtitle Mode）**

- 中文大字，英文小字附于下方，英文默认可隐藏。
- 支持悬浮置顶、拖动、缩放、透明度与字号调整。
- 以当前字幕为核心，避免界面冗余。
- 临时字幕变化尽量平滑，不频繁跳动。

**B. 转写窗口（Transcript Mode）**

- 按时间展示双语字幕。
- 支持历史滚动、文本搜索、复制。
- 能查看最近几句的修订结果。
- 手动查看历史时停止自动滚动。
- 提供一键返回最新字幕。
- 可切换英文、中文或双语显示。

两种界面共用同一课堂会话和实时引擎。

## 5. 课件知识增强

### 5.1 文档导入与解析

支持 PDF、PPT/PPTX，提取：

- 课程主题、章节和文本。
- 专业术语及正确拼写。
- 专业缩写、全称与对应中文。
- 重要概念、定义及相关上下文。

对无法直接提取文字的内容可采用 OCR 等补充处理。

### 5.2 识别与翻译增强

采用两层增强：

1. **ASR 阶段：** 将相关专业术语作为模型提示或热词候选，尽量改善原始语音识别。
2. **翻译阶段：** 结合术语表及最近上下文保持翻译一致性，并谨慎修复有依据的识别错误。

优先采用轻量术语索引与上下文检索，不引入不必要的复杂 Agent/RAG 架构。

保留原始识别结果，避免知识库错误引导。

## 6. 历史录音导入与离线处理（Import Mode）

### 6.1 多段录音导入

- 支持 M4A、MP3、WAV、FLAC 等常见音频格式。
- 支持单段及批量导入。
- 支持拖动调整录音顺序。
- 多段录音可统一归入一节课堂。
- 可混合管理历史录音和软件实时录音。
- 可关联当前课程或课堂的 PPT/PDF。
- 保留原始文件，不强制物理合并。
- 使用统一逻辑时间轴组织转写，同时保留原始片段时间信息。

### 6.2 后台转写与翻译

- 支持对单段录音或整节课堂进行处理。
- 按指定顺序识别多个音频文件。
- 应用不要求实时低延迟，可以采用更注重准确率的处理策略。
- 支持课件术语增强及跨段上下文。
- 自动生成带时间戳的双语转写。
- 支持查看进度、取消任务、失败重试及断点续处理。
- 关闭处理窗口不应终止正在运行的后台任务；应用退出后的任务恢复以持久化进度为准。

实时课堂与历史录音导入复用相同的 ASR、翻译、知识增强和存储模块。

## 7. 课后处理与 AI 总结

### 7.1 高质量重处理

用户可以对实时录制的课堂手动启动高质量重处理：

- 使用完整音频与更充分的上下文重新识别。
- 校正专业词、标点和翻译表达。
- 保留实时版本与重处理版本。
- 不直接覆盖原始记录。
- 可以选择处理单段或整节课堂。

### 7.2 AI 课堂总结

支持结合课堂转写及相关课件生成：

- 课堂摘要。
- 核心知识点。
- 专业术语和概念解释。
- 重点内容整理。
- 结构化学习笔记。

支持用户配置 DeepSeek 等兼容 API 的服务。

无 API 时，自动提供 Prompt 模板及材料导出方式；配置 API 后，可在应用内直接生成、查看、复制和导出总结。

云端请求需由用户主动触发，清晰提示将发送的数据；API 密钥存储于 macOS Keychain。

三小时长课程的总结应考虑分块提取与整体整合，避免输入超长或遗漏内容。

### 7.3 数据导出

至少支持：

- Markdown：双语课堂笔记及 AI 总结。
- TXT：纯文本转写。
- SRT：时间戳字幕。
- JSON：结构化转写及片段信息。
- 原始录音文件。
- 可复制的课堂总结 Prompt。

录音片段移动、增删或重新排序时，应将受影响的全文转写和总结标记为可能过期，允许重新生成。

## 8. 技术架构

### 8.1 推荐技术栈

| 模块 | 技术方向 |
|---|---|
| macOS 界面 | SwiftUI |
| 音频采集 | AVAudioEngine |
| 后台处理服务 | Python / AsyncIO |
| ASR | Qwen3-ASR 0.6B / 1.7B |
| 本地推理 | MLX 优先 |
| 翻译 | Hy-MT2-1.8B 候选 |
| VAD | Silero VAD 或轻量替代 |
| 文档解析 | PyMuPDF、python-pptx |
| 音频处理 | FFmpeg / 原生音频能力 |
| 数据库 | SQLite |
| 文件存储 | macOS 本地文件系统 |
| 云端总结 | 可配置 OpenAI-compatible API |
| UI 与推理通信 | 本地 IPC / WebSocket |

以上为初步候选，最终模型及运行时由实际性能测试决定。

### 8.2 模块划分

- **Course Manager：** 课程、课堂及文件管理。
- **Session Controller：** 录音、转写、翻译状态控制。
- **Audio Service：** 音频采集、录制、导入及音频分块。
- **ASR Engine：** 流式和离线语音识别。
- **Context Manager：** 课件解析、术语索引与上下文管理。
- **Translation Engine：** 实时与离线翻译。
- **Revision Engine：** 字幕稳定、语义校准和版本管理。
- **Task Manager：** 后台任务、状态和恢复。
- **Storage Service：** 文件、元数据及字幕持久化。
- **Summary Service：** AI 总结与导出。

**关键架构原则：**

录音、ASR、翻译、字幕修订、UI 与后台任务应尽量解耦。任何单一模块变慢或发生错误，都不应直接造成已经录制的数据丢失。

## 9. 性能与可靠性要求

以下均为工程测试目标，而非已实现的性能保证。

| 指标 | 目标 |
|---|---|
| 首个有用的中文初译 | 尽量在对应语音之后 1–2 秒出现 |
| 初译尾部延迟 | 力争 P95 ≤ 4 秒 |
| 翻译修订 | 最近 1–3 句 |
| 长时间工作 | 至少 3 小时 |
| 连续录音 | 不因模型推理而中断 |
| 音频导入 | 支持多段和常见格式 |
| 资源占用 | 适配 Mac M5 16GB |
| 离线能力 | 核心录音、ASR、翻译均可离线 |
| 可靠性 | 数据增量保存、异常恢复、任务可重试 |

需要专项测试：

- 重口音及快速语速下的 WER 和专业术语准确率。
- 有/无课件增强的识别差异。
- 初译与稳定译文的延迟分布。
- 三小时使用时的内存、发热、续航和处理积压。
- 多次开启、暂停、关闭处理功能的状态可靠性。
- 多音频片段排序、导入、移动及重新生成转写的正确性。

## 10. 开发计划

### Phase 0 — 模型可行性验证

优先在真实课堂录音上测试 ASR、课件增强和翻译。

验证 Mac M5 16GB 上的准确率、延迟、内存及持续推理表现。

**结果：** 确定实际可用的模型组合和性能范围。

### Phase 1 — 核心音频与离线处理

完成音频导入、分段管理、ASR、翻译及后台任务。

支持将多段历史课堂录音按顺序生成双语转写。

**结果：** 获得可实际使用的离线课堂转写原型。

### Phase 2 — 实时处理与独立控制

完成实时音频采集、流式识别、增量翻译、上下文修订及录音/转写/翻译独立控制。

**结果：** 能在同一课堂内自由开始、暂停和恢复实时处理。

### Phase 3 — 课件知识增强

实现 PPT/PDF 解析、术语提取、ASR 上下文提示及翻译术语统一。

通过真实课堂音频验证增强效果。

**结果：** 专业领域识别与翻译准确率得到可衡量的改善。

### Phase 4 — macOS 应用与课程管理

实现 SwiftUI 原生界面、课程文件夹管理、双显示模式、拖放排序、设置与模型切换。

**结果：** 形成简洁、完整、适合日常使用的 macOS 应用。

### Phase 5 — 课后工作流与稳定性

实现高质量重处理、总结 API、Prompt 模板、数据导出和完整长时间稳定性测试。

**结果：** 完成从实时听课、历史录音导入到课后整理的完整闭环。

## 11. 暂不开发的功能

为保持项目精简，第一版不考虑：

- 复杂 Agent 系统。
- 实时云端 ASR/翻译。
- 多人会议管理及复杂说话人分离。
- 中文语音播报。
- 账号、云同步和多设备协作。
- 跨平台客户端。
- 复杂笔记编辑器。
- 自动多模型路由与大规模模型训练。

## 12. 最终验收标准

LectureFlow V1 应能够：

1. 在 MacBook Air M5 16GB 上运行本地实时识别与翻译。
2. 面对口音明显、语速较快的教师，提供可用且语义可靠的双语字幕。
3. 通过 PPT/PDF 提高专业术语识别和翻译表现。
4. 快速给出初译，并根据后文有限修订。
5. 在同一课堂内自由开启、暂停、停止录音/转写/翻译。
6. 支持三小时课堂及多次中断，不丢失已保存的数据。
7. 支持多段历史录音导入、排序、后台转写及统一总结。
8. 使用类似 Finder 的极简课程文件夹管理方式。
9. 支持课后高质量重处理、AI 总结和常用格式导出。
10. 核心功能不依赖互联网及付费 API。

## 13. 核心开发原则

**优先级：**

识别准确率与语义可靠性 → 实时响应 → 录音及数据可靠性 → 课件增强 → 日常交互体验 → 附加功能。

**架构原则：**

自主开发产品与核心工作流，但不重复造已有成熟基础模型的轮子。

**产品原则：**

让用户自由决定什么时候录音、什么时候翻译、什么内容值得保存，并能像管理普通文件一样管理所有课堂资料。

**最终目标：**

让 LectureFlow 成为一个轻量、可靠、长期免费使用、真正适合大学专业英语课堂的 AI 学习工具。
