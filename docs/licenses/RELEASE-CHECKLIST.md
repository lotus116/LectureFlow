# 二进制发布许可检查

本清单是工程核查，不是法律意见。后续正式发行前逐项完成，不能用源码仓库新增
LICENSE 代替实际二进制检查。历史 v0.6.5 附件不会因本次提交而自动更新。

1. 从已确认的干净提交构建。核对主线贡献来源和新增第三方内容的授权范围。
2. 提供与二进制 **同一提交** 的完整应用对应源码、构建／安装脚本及依赖版本。
   明确发布页源码下载位置、包内 build-info 提交和校验和，不只给主分支主页。
   Python sdist 仅包含 Python 包及许可材料，不是完整桌面应用对应源码；完整
   应用源码应由已审查 Git 提交导出，另配第三方对应源码，排除未跟踪研究文件。
3. 对每个平台生成实际依赖清单，保留完整原始版权／LICENSE／COPYING／NOTICE。
   检查冻结后的文件及 EXE 内资源，不假定 PyInstaller 会自动收集元数据。
   人工核对 Python 标准库、Tk/Tcl、PDFium、TkDND、PortAudio、sherpa-onnx、
   llama.cpp 及所有随附 DLL 的许可，不能只列顶层 Python 包。
4. FFmpeg：运行实际二进制的 `-version`、`-buildconf`、`-L` 并记录 SHA-256。
   获取与该构建吻合的 FFmpeg 及所链接库的对应源码、补丁和构建脚本，选择适用
   GPL 条款下有效的源码交付方式并在同一下载地点明确提供。普通主页、最新源码、
   版本号和无版本构建脚本均不自动满足精确对应源码义务。
5. LGPL 组件：保留许可和对应源码，提供实际适用的替换／重建途径。pystray
   冻结入 EXE 时需要验证修改后重新构建的路径；如果按 GPLv3 许可兼容方式整体
   分发，也不能遗漏 pystray 及相关对应源码。记录用户安装／修改限制。
6. 模型：保留固定版本模型卡、上游版权／许可／NOTICE、转换说明和来源链。
   Windows Qwen 的镜像到 ModelScope 的精确版本链需补齐，或换为已验证来源，
   但更换默认模型须另行确认并验收，不能用许可修复静默改变识别行为。
7. 素材：确认应用图标／同人素材的使用与分发依据；音乐需要相应视听同步与
   再分发许可。署名、AI 生成或 GPL 排除声明均不等于获得授权。不能擅自把他人
   资产放进 GPL 授权范围。
8. 运行 `python3 scripts/check-licenses.py --release`。所有登记的阻塞项都必须
   有可检查的解决证据；正常 CI 的结构检查通过不等于此发布门槛通过。
9. 对最终 ZIP 重新检查声明、源码交付位置、版本与哈希，运行打包后的启动检查。
   用户明确授权正式发布后再发布，且核对远端准确提交与 CI。

`scripts/collect_licenses.py` 只做收集与清单生成，不是自动法律合规认证。
工作流在仍有阻塞时拒绝正式发行，但允许开发和本地核查包继续构建。
