# LectureFlow V1.4 实施与验收计划

基线：`PRD-v1.4.md`。不承诺未经测试的模型性能。执行方式：小步实现 → 行为验证 → 开发者审查 → 记录证据 → 下一步。

2026-10-30 用户更新：先完成可直接上手的应用，人工质量、延迟、续航与长时评估暂缓。下列性能验收条件仍保留，但不作为本轮代码交付前置门槛，不标记为已通过。本轮交付范围见 `DELIVERY.md`，实际证据见 `STATUS.md`。发布采用轻量独立应用；首次打开自动后台下载默认模型并持久化缓存。

## Phase 0：模型可行性（当前）

1. 项目内隔离 Python 环境，固定依赖；记录系统与模型版本，保存本地诊断报告。
2. 只读检查用户指定录音，按显式清单裁剪代表片段；不上传录音。
3. Qwen3-ASR 0.6B/1.7B 对照：相同音频、无提示/课件术语提示，保存原始识别、冷加载、暖推理、RTF 和进程峰值内存。
4. Hy-MT2-1.8B：先验证实际模型架构与 MLX/Metal 兼容，再决定量化和运行时；保留失败证据，不静默换模型。
5. 流式回放同时计量首英文、首有意义中文、稳定中文；离线整段耗时不能当成实时延迟。
6. 人工参考转写可用后计算 WER；没有参考时显示未评估。中文质量与有用性须听音复核。
7. 短样本通过后，做 30 分钟与 3 小时连续测试，记录内存趋势、热状态、积压、丢帧与处理落后量。

退出条件：两个引擎本机可运行；真实课堂质量经复核；持续处理不累积积压；记录达到/未达到延迟目标的实际范围。未过门槛仅完成验证工具与可复用基础，不冻结后续模型选型。

## Phase 1：音频与离线原型

顺序：SQLite 迁移和目录结构 → 导入/排序/时间映射 → 持久化任务 → ASR/翻译流水线 → 版本与导出。

验收：三段录音显式排序，后台生成统一双语转写；取消后无伪完成，异常重启从已提交检查点继续；失败重试无重复字幕；源文件哈希不变。调整片段后旧全文/总结标记过期。

## Phase 2：实时与独立控制

顺序：AVAudioEngine → 独立分块写入 → 有界推理队列 → 流式适配 → 初译/有限修订 → 三开关状态机与异常恢复。

验收：8 种开关组合均正确；每次恢复生成逻辑新片段但留在同课堂；推理故障不影响录音；暂不支持无损实时推理追赶时明确告知积压，绝不无限缓存。

## Phase 3：课件增强

顺序：PDF/PPTX 文本与来源页 → PPT 转换/OCR 回退 → 术语表 → ASR context → 翻译约束 → 对照评估。

验收：同一音频有/无课件对照，专业词准确率有可衡量改善且不增加无依据改写；保留原始识别。

## Phase 4：原生应用

顺序：SwiftUI 三栏工作空间 → 文件/片段拖放 → 全文/悬浮双显示 → 输入设备/模型设置 → 本地 IPC → 首次引导和模型管理。

验收：通过 PRD §12 的课程管理和自由控制场景；窗口关闭不终止任务；历史浏览不抢滚动；模型切换不丢音频。应用签名、麦克风授权和打包另行验证。

## Phase 5：课后与稳定性

顺序：完整重处理版本 → Prompt/多格式导出 → 可选云端摘要与 Keychain → 长课程分块总结 → 3 小时与故障注入 → 应用打包。

验收：断网核心可用；未主动请求不会发送云端请求；摘要标示材料版本；3 小时报告包含实际测量而非估算；异常可恢复已提交录音/字幕/任务。

## 每次交付的审查门槛

- 需求和验收是否对应；未完成项是否透明。
- 录音是否可能被推理阻塞；文件/数据库操作是否存在不一致窗口。
- 时间轴和版本是否能在排序、移动、重试后保持可追溯。
- 日志和版本库是否混入音频、课件、转写或密钥。
- 用例验证是否覆盖重要失败路径；指标是否明确测量起点和边界。
