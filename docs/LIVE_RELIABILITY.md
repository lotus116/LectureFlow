# 实时字幕算法与验证边界

## 设计

- 音频保存继续由原生采集独立执行。识别和翻译共用单一推理线程，避免 MLX 并发访问。
- 恢复依据输入与处理音频时间、进度事件和推理耗时。文字相同、静音、重复或结巴本身均不触发恢复。正常静音也产生音频处理进度。
- 单次无进度期限至少 180 秒，随已完成推理耗时自适应。每次采集最多恢复三次，退避 2、4、8 秒；失败进程终止后才恢复字幕。缺口写入本地诊断，原始录音独立保存。
- 内部识别保留 12 秒上限。低能量检测使用有上下限的噪声估计与迟滞，句末与未完整短句采用不同停顿期限。保留前置音频与尾部静音。
- 阅读段落由连续、未完整的短片段拼接，只拼接原文并保留各片段时间映射与原始修订。限定段落时长与片段数，遇到缺口或结束立即收尾。
- 临时翻译处理最新原文；稳定初译与上下文回改均为必做任务，按目标片段合并后文依据、保留首次排队时间并公平调度。积压只延后回改，不删除它；退出修订窗口前先补做再锁定。课件二次识别仍与必做翻译分开调度。
- 课堂反馈修正后，新任务默认保存固定英语模式，旧任务缺失配置时按英语恢复。纯中文原话直出，含英文的混合句交给翻译模型并要求保留中文、否定和纠正。

## 验证边界

本页记录设计，完成情况以 STATUS 和行为测试为准。能源检测无法区分老师和同学，也不能确诊此前字幕重复的原因。自动语言接口支持不等于中英混合识别质量已验收。有限超时无法证明推理永远不会超过阈值，超过期限按处理不可用记录并保留源录音供后续转写。

## 实现参数与限制

- 16 kHz 音频按约 0.25 秒输入，原生写管道队列仍为八包；Python 读入线程独立排队，上限调整为 240 包（常规音频约一分钟，控制消息也占容量），用有界内存吸收短暂推理积压。持续超载超过容量仍可能丢弃字幕音频并计数，源录音另行保存。稳定初译／回改任务按目标片段合并，正常返回时最多三条；加入第四条时先完成最老目标再锁定移出。失败时保留该待办并报告，不伪装为完成。
- 能量阈值为估计噪声的三倍，限制在 0.002–0.008，语音持续阶段使用 0.7 倍迟滞。噪声估计仅在非语音阶段更新。该方法仍是能量启发式，持续背景噪声与远处人声的区分尚待真实验证。
- 完整标点后的停顿为 0.65 秒，其余为 1.25 秒，识别片段仍上限 12 秒，起始保留前一包音频。阅读层只连接同会话、间距不超过 0.35 秒的未完整短片段，最多三片段、总长 12 秒。原始修订、源区间与导出记录逐片段保留。
- 临时译文不再依赖句末标点，距离上次翻译一秒且没有必做任务时可获调度；高积压时暂缓，等待六秒后仍可获调度。这不是一秒端到端延迟承诺。稳定初译与回改共用 FIFO：积压降至两包以内，或最老任务等待至少六秒时，每轮执行一项；持续讲话、当前识别段未结束均不阻止回改。新后文只更新依据，不重置任务等待时间。退出最近三段窗口前、正常停止／切换输出开关时排空相关任务再锁定。只有课件二次识别保留空闲时最多每 20 秒一次的预算，回改不占此预算。
- 看门狗不观察文字是否变化。已收到音频但处理无进展超过 `min(600, max(180, 最长已完成单包处理耗时×8))` 秒时终止字幕子进程，初次准备允许 300 秒。识别器累计接收超过四秒音频而内部 chunk 计数不前进时也报告异常。上游原有重复检测与窗口保护继续使用。
- 故障恢复最多三次，退避 2、4、8 秒。恢复使用当前保存开关。达到上限后禁止自动协调再次开启字幕，用户暂停再继续可重新尝试。正常暂停／结束接收已登记旧进程的尾部字幕，新进程等待旧链路收尾；故障进程事件隔离。
- `Logs/live-health.json` 保存最新数值快照及当前会话最近 64 个缺口，包含输入／处理音频时间、单包推理耗时、积压、两侧丢包与恢复标记。日志不含课堂文字或音频，模型任意 stderr 不写入应用日志。历史缺口超过上限会被滚动替换。
- 稳定原文先落库，再完成翻译。进程被终止时少量待译片段可能仍未完成，界面明确提示；已有原文遵循保存开关保留。仅字幕且未保存音频时，无法从源录音补齐缺口。
- 新会话／版本默认英语，保存 `source_language` 与 `language_policy=2`。旧会话／版本缺失配置时仍按英语处理。自动模式每个识别片段交给上游检测，不按临时文字在应用层反复切换语言。实时 JSON 导出包含会话语言配置。

## 上下文回改恢复 · 2026-11-04

依据 PRD §4.4、§9 和最新设计 §3.4，本轮恢复前两段随新后文校准，保留当前段共三段可修订窗口；固定英语默认不变。每次稳定原文先保存，再登记自身初译与前两段的回改；同一目标未执行的任务合并最新可用的后两段，不丢掉等待中的目标。输入给翻译的是有限的真实前文（最多 1200 字符）、后文（最多 1000 字符）及相关可信术语，课程大纲不作为老师原话。

完成回改才允许锁定，旧原文和修订历史仍保留。正常暂停／结束会通过现有停止协议排空；进程被杀死、系统退出或模型持续失败不等同于正常排空，内存待办尚未实现跨进程恢复，不能写成故障后全部回改可恢复。正常退出等待已获得后续批准并完成，见下方收尾说明；异常强杀待办持久化仍需另行讨论。

自审还修复了两个相关问题：片段稳定时先前可见的临时译文不再被清空；重复说出相同短语的新片段仍可产生初译。课件二次识别若接受了英文修正，也重新登记相关回改，不以无后文翻译覆盖校准结果。新增数字诊断 `translation_pending`、`translations_completed`、`context_translations_completed`，不增加课堂文字日志。

新增行为测试直接覆盖产品使用的延后调度路径和真实协议入口（模型为可控替身），而非仅覆盖同步旧分支：连续讲话、短暂积压、截止时间不重置、前两段都有后文、100 段压力下有界且锁定前完成、停止排空、保存开关、推理失败不伪锁定、重复短语初译及短暂输入积压的顺序保留。真实回放只用于验证模型链路与调度实际执行，不替代听音语义验收。

## 正常退出等待 · 2026-11-04（A01 / SD-04、07、08）

- 采集停止后异步等待音频写入队列封存，包括已暂停但仍打开的录音；主线程不阻塞等待磁盘。录音／取消录音回调先在生产队列领取待办，再派发数据库登记，从而消除“队列已空而登记还未开始”的提前退出窗口。
- 正常退出先进入保存状态，等待录音登记、全部字幕子进程及本应用启动的后台任务结束，然后再次提交退出请求。保留普通事件循环，避免系统模态退出等待阻塞主队列中的异步登记。收到 `stopped` 还不够：必须读完输出、子进程成功退出，且没有错误或未完成翻译计数。异常 EOF、非零退出和保存失败保留警告，不能自动退出。
- 正常字幕收尾不再按停止后固定超时强杀；原有采集中无进展的恢复逻辑保留。积压较多时继续补做，窗口可取消退出。取消仅留在应用，不恢复麦克风；重复退出不创建第二组收尾工作。错误提示可明确确认带着未完成内容退出。
- 收尾期间禁止新的采集、任务和自动模型启动；后台 worker 收到正常终止请求并保留已提交检查点，模型下载停止。只等待本应用管理的后台进程，不终止用户单独启动的命令行任务。
- 129 项 Python、35 项原生行为测试通过（33 Core + 2 App，后者驱动真实字幕子进程）。新增覆盖暂停后封存、异步登记未完成、多个待办逆序完成、磁盘失败、重复封存、停止消息早于进程退出、异常退出／无停止消息／剩余翻译不判成功。真实硬件故障、强杀后的待办恢复和三小时仍未验收。
