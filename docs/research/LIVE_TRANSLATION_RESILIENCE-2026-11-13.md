# 实时翻译失败隔离与可选刷新节流 · 2026-11-13

## 交付决定

按用户授权实施①翻译失败隔离、②减少已有临时中文的重复刷新，并完成正常语速长课验证。保留首次中文、前两段必要回改及产品 20 秒 ASR／字幕窗口。

- **①默认生效**：推理失败不再直接终止字幕处理；同一输入最多两次尝试，正常重试冷却六秒。失败期间其他字幕可以继续；仍未完成的工作持久记录，保留旧译文、不锁定、不计成功。窗口退出／停止可使用剩余重试，之后释放实时队列。保存错误仍向上报告。
- **②实现为实验选项，默认仍为 1 秒**：`live run --temporary-refresh-seconds 3` 只减少已有临时中文的重复刷新；首次中文仍用一秒门槛，必要回改继续。首轮配对发现延迟退化，反向诊断的方向又不同，不能安全提升为默认。桌面正常调用保持原频率，未新增设置页。
- **③正常任务优先级重排未实施**：健康任务保留原有 FIFO。仅跳过失败冷却／重试耗尽任务，避免故障拖住其他内容。

Mac 后台直接保存失败记录，收尾阶段继续传递本会话告警。Windows 通过与字幕同一 FIFO 的事件队列保存记录；成功字幕先保存，再清除失败记录。关闭英文保存时，不持久写入原句／上下文／异常原文。JSON 历史导出包含未完成记录；尚无跨进程自动重试入口，也不声称修复强杀恢复。

## 正常语速真实模型回放

基线为 `19a6c44`。250 ms 音频包以 1× 输入，240 包缓存；真实本地 Qwen3-ASR 1.7B 8-bit 与 HyMT 1.8B 4-bit，模型文件及运行源码按 SHA-256 冻结。候选沿用产品 20 秒窗口，未使用研究中的 30 秒配置。每次结果保留原始输入／消费帧数、队列、调用耗时、发布事件和主机供电样本。

### 已复现故障的结果

72 分钟 ITA2 在约第 54 分钟再次遇到与历史故障完全相同的原句／前文／后文输入，真实模型仍生成截断结果。新实现记录失败并继续识别，加入下一段真实后文后翻译成功；全部 312 段最终有中文。这证明故障已被隔离，**不证明相同输入重试必定恢复，也不证明重复生成问题已经消失**。

另对最终核心源码单独重放固定真实故障输入：两次调用均实际截断，旧译文保留，状态为 stable；下一正常句成功并锁定。真实 SQLite 中保留一条 deferred 记录，成功计数为一、失败尝试为二、实时待办为零。该试验保留了原提示、模型和 512 token 上限；属于已知缺陷回归。

### 为什么没有默认开启 3 秒

第一轮从原版 1 秒到候选 3 秒，翻译实算减少 19.1%，但首中文 p95 从 7.98 升到 18.30 秒，首英文也退化；与此同时 ASR 实算由 366.1 增至 462.5 秒、单次推理耗时和主机负载上升。两次最终英文、句界和中文一致。

反向诊断先跑 3 秒再跑 1 秒，首中文 p95 分别为 7.89／22.25 秒，翻译实算分别为 256.7／375.8 秒，最终英文、句界和中文仍一致。运行间供电由电池省电转为接电正常模式，且期间存在短时无模型回归测试并行，不能把差异全部归因于刷新策略。没有为获得好结果调整识别参数或确认集阈值，也不以反向结果覆盖首轮退化。

最早两堂及首轮配对均在电池省电条件下；第一堂开头还与无模型原生构建短暂重叠。最终默认整堂期间未再运行测试或构建，逐分钟记录均为接电正常模式；首中文 p95 仍为 12.35 秒，长尾问题尚未解决。这些数据支持验证连续运行和故障隔离；不足以证明跨设备、热状态或课堂下稳定的延迟收益。

## 回归与边界

本地 Python：307 通过、5 项 Windows 专用测试跳过。覆盖连续 100 次失败的有界内存、有限重试、首次中文、两段后文、保存开关、数据库重开、成功保存后才清除失败记录、真实后台停止协议，以及 Windows 事件到真实 SQLite 的四种失败／恢复与保存组合。Windows 的便携测试不等于实机验收。

最终原生检查：49 通过、1 跳过；wait／repeat／failure／cancel 四类实际 AppKit 退出探针通过。提交状态见 [STATUS](../STATUS.md)。当前验证不包括真实麦克风、Windows 实机、三小时单堂、中文语义准确率、声音增强或课后模型质量；长回放的 publish 回调不是完整桌面端到端测试。此次不改模型、提示、token 上限、录音原轨或历史版本，不正式发版。
