# 中文回改目标隔离修复与离线对照 · 2026-11-05

关联SD-04/05/08、LF-04/09/11。用户明确批准修复中文回改混入邻段的问题、保留必做回改、完成修复前后离线验证；先不正式发版。基线645e732，模型仍为原Hy-MT2-1.8B-4bit固定修订，temperature=0、输出上限512未变。没有上传课堂音频或文本。

## 实现与边界

带后文的回改使用单独JSON对象编码前文、后文、可信术语，当前目标放在翻译任务指令之后。指令明确只译当前字幕、不加入参考信息、不补全未完句，保留否定、数字、自我纠正和重复。参考文本中的引号／换行由JSON转义，避免和目标连成一段。无后文的初译继续使用原提示，纯中文直通及术语匹配入口保持原行为。

新增输出检查针对空译文、内部提示标记、上下文JSON字段泄漏。发现这些可观察异常即抛错，不把污染文本交给保存／发布入口。原队列在翻译成功后才覆盖旧译文、删除待办并增加完成数；测试验证拒绝后旧译文、任务身份和计数保留，后续成功重试可以完成。没有把被拒绝任务算完成，也没有改成跳过回改或用无上下文结果冒充回改。

实现入口：[translation_policy.py](../../src/lectureflow/translation_policy.py)、[adapters.py](../../src/lectureflow/adapters.py)。未改ASR、录音、人工编辑保护、字幕源版本、队列调度或前两段回改范围。错误仍走既有错误处理，未新增跨进程恢复；实时强杀待办恢复A01b仍开放。过滤器不判断所有语义，尤其不能靠没有提示标记证明译文未混入邻段。

参考了[Hy-MT2官方翻译指令示例](https://github.com/Tencent-Hunyuan/Hy-MT2#hy-mt2-translation-task-instruction-examples-chinese-english-comparison)中目标与参考信息分开的任务表达，实际方案由本地对照选择；不声称官方模板保证修复，也未改用另一模型。

## 对照选择与失败保留

先用此前6个已知实例比较原提示、参考JSON、标签、输出包裹四种写法。首轮参考JSON在6例消除串段；但扩大到原50条基线后，在R-base-23新导入了下一段独立内容，因此首轮判为不合格。标签方案会补全句子，输出包裹方案不稳定遵守标签，未采用。

第二轮开发加入R-base-23，并保留首轮新课堂中发现的词义退化H03。比较更严格的目标指令和目标先置写法，选择前者：恢复R-base-23的目标边界且重复保留较好。H03普通词义退化未解决，不能称总体翻译准确率全面提升。

第二轮规则冻结后，重新选择另一段未用于调参的连续4.2分钟原音，形成21个12秒目标，前后各两段作为上下文。每个目标的英文只生成一次，修复前后共享相同英文、前后文和模型。首轮15条留出已查看，不再冒充第二轮独立留出。无输出筛除，所有21条纳入。来源仍是同课程，不能宣称跨老师泛化。

原50条课堂基线及6个开发反例做最终回归，另有15个合成保护样本：否定、数字单位、重复、自我纠正、混合中文、引号、未完句、字面标签、消歧词和可信术语。后两个术语样本使用App实际的`英文: 中文`格式；早先箭头示例仅是直接适配器输入，不能代替实际格式检查。

## 修复前后结果

下表的错误是“把可定位的邻段独立命题／整段内容导入当前目标”，由本轮助手逐条比较固定英文、前后文与中文判定；不是独立人工听写、盲评或课堂WER。残缺句的短语补全及一般词义错误另列，不能用该计数代表全部质量。

| 分组 | 目标数 | 修复前明确串段 | 最终修复后 |
|---|---:|---:|---:|
| 原始已知反例（3英语、2混合语言） | 5 | 5 | 0 |
| 原投影缺闭引号的单列反例 | 1 | 1 | 0 |
| 原课堂完整基线回归 | 50 | 1 | 0 |
| 第二轮冻结后的新课堂留出 | 21 | 0 | 0 |
| 合成保护／消歧／术语 | 15 | 0 | 0 |

E-hard4与50条基线中的E-base-00输入相同，不能将两组错误简单相加。92条最终配对记录含这一重复；6例开发结果不构成独立泛化证据。新留出原本没有明确串段，能支持本次未新增该类错误，不能据此估计总体串段率下降。

可定位的改善包括：令牌／有效期目标不再混入后文请求；专家报告和法官／报告两个目标不再被后两段整段替代；混合语言两例不再输出上下文标记及邻段全文。投影引号不完整的一例单列保留，不能把它当成App原始输入的同等证据。

15个合成目标均保留本轮检查的关键条件：禁止删除、500MB而非5GB、十五而非五十、重复否定、未完条件、混合中文、可信译名等。相同目标在河流／金融上下文下仍分别译为岸边／银行，计算机语境仍得到鼠标，说明上下文未被关闭。所有最终配对输出无截断；没有实际触发生产拒绝器的样本，拒绝／重试保护由故障注入测试验证。

## 未解决的问题与结论限制

- 首轮新课堂H03把一般操作译为培训；第二轮开发复查仍存在。最终新留出V2-H04把Windows Store译成存储，旧译为应用商店，是新词义退化。两者均保留在证据中，没有把它们算作改善。
- E-base-09仍把未完谓语补成与后文一致的短语；E-base-18旧新均补出未完句的含义。因此**本修复减少已复现的整段／独立命题串译，不保证彻底杜绝所有短句补全**。这种风险不应通过改名隐藏为“消歧完全正确”。
- R-base-17尾部孤立否定在旧新均遗漏，部分混合中文被重述，词义、术语和残缺ASR输入仍可误译。15个合成保护样本通过不能覆盖所有课堂否定或数字。
- 新课堂英文为固定ASR输入，没有原音人工真值；这里只评估中文相对输入的目标范围，不声称提升了语音识别准确率。单模型、小样本、同课程以及助手文本判读限制仍在。

## 计算、连续回放与检查

原50条固定输入：旧／新回改计算合计18.139／18.168秒，中位0.363／0.370秒；第二轮新21条为7.547／7.617秒，中位0.345／0.350秒。原50条是在不同轮运行，21条按目标交替旧新，均为单次本机测量，不宣称统计上无性能成本。没有增加模型调用次数或等待更多后文。

25条最终英文与修复前逐字一致；25条最终中文与本轮固定文本离线对照一致，令牌目标串段在完整链路中也消除。尾延迟口径仍为首次对应事件墙钟减当时音频末尾，首中文可为临时字幕，不是从一句讲话起点计时。ASR代码未改却同样明显更快，说明环境／系统负载差异未排除，**不能把整体延迟下降归功于提示修复**。本轮可确认的是该5分钟没有新增丢包、少做回改或残留待办。

166个Python测试通过，包括真实适配器拒绝提示污染后保留旧译文／待办并成功重试、原前两段回改／积压／锁定／源版本保护，以及初译提示逐字不变。研究脚本实际运行，ruff、文档链接、HTML本地引用及暂存隐私核对通过；原46份来源文件与原SQLite哈希不变。未正式发版、未变更模型、未声称续航或三小时稳定性通过。
