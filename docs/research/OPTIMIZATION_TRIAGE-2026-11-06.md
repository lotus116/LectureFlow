# 优化排查：修复资料误触发与当前句初译等待

发布沿革：下文为开发阶段记录，相关改动已纳入 [0.6.5](../RELEASE-0.6.5.md)。

2026-11-06。用户要求继续探索 LectureFlow 卡住的优化问题。本轮以 `e75db97` 为比较基线，不下载新模型，不打开麦克风，不修改用户资料库。先修正检索缺陷并定位当前句计时问题，随后用户明确要求修复延迟并追溯来源。当前生产代码已采用独立临时初译计时，必做回改、模型与应用默认值保持不变。尚未正式发布。

## 为什么继续扩大提示或换模型还不够

已有本地三轮研究将“给对词能否识别”与“应用能否自己找到词”分开：10场公开技术演讲49个预定目标，16个本机首稿写错，正确单词提示纠回其中9个；另一批自动抽词与选主题却没有修复6个实际目标错误。追加25个新句的局部自动采用同时出现一次改善和一次退化。该观察不是普通课堂准确率，也不支持自动放宽覆盖规则。

这些历史结果来自已有研究，本轮没有重跑ASR或独立复核听音。人工参考资料见 [ACL 60/60](https://aclanthology.org/2023.iwslt-1.2/) 与 [数据说明](https://iwslt.org/2023/multilingual)。专业词候选提取、主题选择、声音支持及最终采用分别有缺口；不能把所有问题归给口音，或用候选变流畅代表实际字幕变准。

## 1. 已修正：短片段被当成领域证据

`term_draft_score` 将复合术语拆成部分后，原先调用的 `similar` 对任意子串包含返回真。因此单独的 in 能同时支持 Reversing 和 Engineering，也能支持 Windows 和 binary，整词得到1.0分。提高0.8选择阈值不能拦住这种满分误匹配。

修复仅用于提示检索与相关页打分：完整词相同仍匹配；非完整词至少双方四字符，并达到原有相似度阈值，不再因任意包含直接算相似。不改提取器、提示上限、接受门、ASR、翻译或必做回改。候选接受使用的旧 `similar` 独立保留，此修复不代表它具备声学置信保证。

### 本轮证据

- 两条普通口语负例每句从3个无关提示降到0：`We are in this example.`、`I will be in the room.`。
- 混合正例 `virtural memry` 和 `create file` 仍找到 VirtualMemory／CreateFile，同时移除3个由 in 误触发的词。另保留 Export Directory、Reversing Engineering、export directry 和 MemoryProtection 的既有检索。
- 新增21个参数化／集成测试：短词反例、完整词／轻微拼写容错、相关页包含误判、真实生产离线入口和实时 polish 路径。后两项使用假模型验证无关口语不会触发第二次模型调用，原字幕不变。
- 对已有49条公开ASR首稿做CPU检索回放，两组分别使用原始公开论文摘要和未改变的生产提取器，抽出21／40条候选。提示条目总数83→37，非空查询39→25；预先标注目标进入提示名单仍为15/49，没有丢掉这15条。

49条是已有诊断集，不是新留出。目标词仅用于检索后的计数，不输入检索；剩余34条目标仍未被选中。没有完整相关词标注，不能把减少的46条全称为误提示，也不能宣称真实ASR准确率、召回或时延已改善。本轮不重新解码音频，除明确的合成反例外，只证明输出更收敛且这15个目标被保留。

## 2. 新定位：稳定段翻译会重置当前句的初译等待

修复前的生产 `CaptionEngine.service()` 先处理稳定段必做队列。只要队列非空，即使本轮受积压限制未执行，也提前返回；当前正在讲话片段的临时初译只能排在后面。每次 `complete_translation()` 又更新共享的 `last_translation_at`，于是当前句在必做队列清空后仍可能重新等待1秒或6秒。

既有测试证明前两段必做回改不会被饿死，却未覆盖“当前句已出现英文但一直没有中文”的竞争情形。过去按字幕音频末尾计的首中文尾延迟，不等于英文首次可见到中文首次可见的等待。

### 历史来源与修复范围

`git show` 与逐行追溯确认：2026-11-04 的 `0062151`（双语推理调度）已有稳定段翻译后写共享计时器的逻辑，随后 `4bb4641`（保留必做上下文回改）沿用。最近的 `e75db97` 课件批量导入修复没有修改 `live.py`，不是该次导入改动引入。Git 作者不能独立证明是哪一轮助手操作，亦不能据此把所有课堂延迟都归于这个问题。

当前修复将字段明确为 `last_temporary_translation_at`，在每个新有声片段开始、调用 `init_streaming` 之前启动自己的计时，因此首次ASR耗时计入等待；只有当前临时初译成功才更新计时。旧稳定段初译／上下文回改完成不再改它。每个新段仍清空临时去重文本，重复说出的相同英文不会被跳过。FIFO、排队年龄、1秒／高积压6秒门槛、每轮一个任务及停止排空均保留。这消除队列排空后的额外等待，不是保证1秒或6秒出中文。

新增12个参数化行为测试覆盖：旧上下文回改完成后的下一次服务、不足／达到独立门槛、长空闲后新句、慢ASR计入等待、增量英文限频与去重、临时翻译失败不标完成并可立即重试。既有重复句、源版本、失败保留、仅中文模式和必做回改保护继续运行。

### 可控模拟与生产修复

250毫秒合成音频包，4个各0.25秒并强制结束的短稳定片段后接12秒当前片段；假翻译每次消耗0.35、0.7或1.3秒。积压参数固定为0、3、8包。记录英文首次发布到中文首次发布，保留FIFO、队列年龄、前两段回改及停止排空。诊断分别加载固定提交的旧 `live.py` 与当前生产类；当前片段按自身开始时间计时，稳定段翻译不再重置这个计时。

| 假MT成本 | 固定积压 | 修复前等待 | 生产修复后 | 必做／带后文完成数（两者相同） |
|---|---:|---:|---:|---:|
| 0.35秒 | 0包 | 2.80秒 | 1.80秒 | 9／5 |
| 0.70秒 | 0包 | 3.60秒 | 2.85秒 | 9／5 |
| 1.30秒 | 0包 | 5.40秒 | 4.65秒 | 9／5 |
| 0.35秒 | 3或8包 | 12.90秒 | 7.15秒 | 7／5 |
| 0.70秒 | 3或8包 | 14.05秒 | 8.30秒 | 7／5 |
| 1.30秒 | 3或8包 | 15.70秒 | 9.95秒 | 7／5 |

18组场景（包括无先前片段对照），每组旧生产／新生产共36次CPU模拟。全部停止后待办为0，逐项比较必做调用的目标原文／前文／后文顺序及锁定结果，其哈希在18组对照中均一致。没有先前队列时两者相同：无积压1.35–2.30秒，有积压6.35–7.30秒。修复没有通过少做必做回改取得表中改善，但仍有明显剩余等待。

这不是实际输入队列的实时仿真：积压是固定输入参数，3和8都只代表大于2的同一分支，并非两个实测负载等级，未根据CPU/GPU处理速度或新包到达重新计算；假翻译成本只推进模拟钟，假ASR不消耗计算时间且每段文字固定。它能隔离“其他段翻译重置当前计时”的控制流效应，不能证明真实P95、丢包、耗电、整体吞吐或所有回改任务的等待都不变。当前生产修复已经应用相同的独立计时边界，尚未正式发版。

## 3. 同一公开连续音频的真实模型短回放

使用既有官方ACL压缩包中的 `2022.acl-long.410.wav`，固定45–105秒区间，共60秒；相同本机、Qwen3-ASR 1.7B 8bit与Hy-MT2 1.8B 4bit固定模型。通过 `scripts/smoke-live.py` 的真实250毫秒输入节奏，顺序运行旧 `e75db97` 与本轮生产修复，各一次。不启用课件或口音增强。每次创建并清理独立临时资料库，不打开麦克风；源文件哈希前后相同。最初沙箱因无Metal设备未能启动模型，之后获准使用本机Metal完成两次回放，失败记录未冒充结果。

两次处理的240个音频包时间序列相同，最终9段的起止、英文和中文逐项相同。真实必做调用序列不完全相同：修复版本先完成了第1段只带第2段后文的一次中间回改，之后仍完成第1段带第2、3段的完整回改；旧版在执行前已合并两段后文。因此不能把合成实验的“调用序列完全相同”套到真实回放，但没有靠删除必做回改获得改善。

这一次样本中位等待明显缩短，最慢段没有改善；更早临时初译同时增加中文变化次数，停止收尾也略慢。样本只有一分钟、每个版本各一次，未随机交替重复，不能将噪声与全部调度效应分离，不报告总体P95或固定加速比例。未独立评分翻译质量，不证明正确率提高；未覆盖三小时、设备／休眠、麦克风、完整界面或真实课堂。调度仍串行，必做队列非空时仍挡住当前临时初译。

本地生成的对照摘要记录逐段首译时间、输入任务哈希与音频处理顺序；公开文档只保留数值和官方样本标识，不纳入用户资料或私人路径。后续复测应保留同样的指标、固定输入和失败记录，而非仅看句尾延迟或吞吐率。

## 4. 接下来应按什么顺序推进

1. **先验收检索小修复。** 保留本轮负例和正例，后续用带词级出处的不同课程查询核查是否错失有用候选；不要先放宽自动覆盖门槛。
2. **扩大当前句计时的连续音频验证。** 本轮已完成上述一分钟双版本模型回放。下一步应跨演讲、短停顿和长连续讲话交替重复，继续记录首中文、变化次数、任务年龄、包顺序、丢包和停止排空。必须保留流式初译和前两段回改，不能用减少任务换好看数字；暂不根据一次样本调整1秒／6秒门槛或启用并行模型。
3. **把资料链路做成可核验信息，再研究更复杂检索。** 区分当前课程有没有资料、目标在原页是否存在、是否进候选、是否被选中、重听是否改变和为何接受／拒绝。优先处理专业单词／小写短语候选资格和人工术语如何生效，不回到“所有长单词都当术语”。这是下一步设计建议，本轮未新增界面或改变词表规则。
4. **继续将自动专业词改写留在离线验证。** 下一批跨课程保留错例与原本正确的保护例，分别统计修复、误改和全句净错误，数字／否定／动作关系另列。没有证据时不集成大范围字幕覆盖、老师分离或更大的课件提示。
