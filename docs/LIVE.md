# 实时基础 · 实验版本

对应 LF-02、LF-03、LF-04、LF-11。核心数据流已经实现；硬件麦克风授权、设备异常与三小时实时可靠性尚未验收。模型质量门槛仍按 Phase 0 保留。

## 控制与保存

| 保存录音 | 英文输出 | 中文输出 | 实际运行 |
|---|---|---|---|
| 关 | 关 | 关 | 不采集 |
| 开 | 关 | 关 | 只写录音，不启动模型 |
| 关 | 开 | 关 | ASR，保存英文字幕，不保存音频 |
| 关 | 关 | 开 | 内部 ASR 与翻译，仅保存中文，不保存英文或音频 |
| 开 | 开 | 关 | 录音与英文字幕 |
| 开 | 关 | 开 | 录音与中文字幕；英文不落库 |
| 关 | 开 | 开 | 双语字幕，不保存音频 |
| 开 | 开 | 开 | 录音与双语字幕 |

暂停保存录音时封存当前逻辑片段；恢复录音建立新片段，课堂不变。未提供“舍弃当前录音”操作，避免将停止误解为删除。

## 采集与恢复

AVAudioEngine 只在主动开启功能并获得麦克风授权后初始化。tap 复制到最多 32 个待处理缓冲；专属串行队列将音频转为 16kHz 单声道，并分别送给录音器与字幕管道。字幕管道写入不在录音队列中执行。

录音内部约五分钟封存一个 16-bit CAF 块，封存时同步到磁盘。一个真实录音目录对应一个逻辑片段，完成后登记 SQLite。多个块不强制物理合并，课后处理按源区间跨块解码。

`capture.json` 记录共享采集 ID、第一帧在采集时间轴上的偏移与实际帧数。实时字幕使用同一采集 ID，保留关联锚点。应用重启后的采集使用新 ID，各会话时间轴独立保留。

“恢复录音”尝试登记意外退出留下的 CAF。活动录音由 OS 文件锁保护，恢复不会读取或重写活动片段。无法解码的块保持原样；恢复部分内容时名称明确标记“部分音频待检查”。当前未完成块能否恢复仍取决于文件状态，不能保证恢复异常退出前的每一帧。

## 字幕与资源

本地 Python 子进程通过 JSON 行接收 250ms PCM 包，不开放网络端口。原生待写音频包和 Python 输入队列分别限于 8 包；跟不上时丢弃字幕待处理音频并提示，不阻塞录音写入。录音写入本身发生错误或严重积压时，明确停止采集，保留已写文件。

ASR 使用最多约 12 秒的活动语音窗口和轻量能量端点检测，避免模型流式状态随课堂持续增长。前一个短静音包作为前滚动保留在内存中。最近三段识别语音可依据后文修订中文；更旧条目锁定。这里以语音片段近似句子，精确句界与语义准确性仍需评估。

原始英文与修订记录分别保留；关闭英文输出时，当前字幕与所有修订历史均不保存英文。只翻译时，内部识别文本仅存在于有界推理上下文中。

实时模式优先使用模型。后台任务在当前处理区间后让出模型锁，并保留检查点；实时处理结束后可继续后台任务。只录音不占用模型。实时中暂时禁用模型选择，句子边界的无损切换仍待实现。

字幕子进程异常退出不会通过 SIGPIPE 终止录音应用；字幕失败时关闭字幕功能，录音开关独立保留。实际硬件、睡眠与设备切换仍需进一步验证。

## 已验证

- 49 项 Python 行为测试；7 项原生测试。
- 8 种组合的原生数据路由与字幕落库约束。
- CAF 分块边界、48kHz 到 16kHz 的尾部刷新、恢复后新建片段。
- 修订锁定、旧数据库迁移、模型互斥与后台让出、部分文件恢复。
- 真正的双语与只翻译流程各回放 30 秒课堂录音：均生成 10 条字幕，输入队列无丢包；原录音未改变。
- 只翻译回放确认资料库没有音频文件，字幕及修订历史的英文字段为空；短测模型活跃内存峰值约 2.11GB。

自动 UI 工具本轮未能取得应用窗口；视觉检查、真实麦克风授权和设备采集尚未验收。原生构建与无麦克风的合成采集测试通过。

## 复现回放

```sh
.venv/bin/python scripts/smoke-live.py '/path/to/class.m4a' \
  --start 60 --seconds 30 --translate-only \
  --output reports/private/live-check.json
zsh scripts/test-native
```

回放不会打开麦克风。首条字幕出现时间不是经人工核验的“有用中文”语义延迟；本轮不据此宣称达到 1–2 秒目标。
